GitHub Pages and maintenance

Preview locally

python -m http.server 8000 --directory docs

Open http://localhost:8000. The site uses static HTML and CSS with local assets; there is no build step, login, external font, or JavaScript framework dependency.

Publish to GitHub Pages

  1. Complete the license, authorship, and third-party distribution review.
  2. Create the intended repository and add the package contents. Do not upload generated results or caches.
  3. In Settings → Pages, choose Deploy from a branch, select the main branch and /docs folder, then save.
  4. Open the Pages address shown by GitHub and check navigation and figures.
  5. Tag the verified software release. Archive that release separately if a persistent software DOI is needed.

These instructions follow GitHub's publishing-source documentation. This package has not been pushed or published by the assistant.

Too many workers / memory pressureBenchmark one model; increase concurrency within available memory.
Zeros in old thermal plotsUse tools/plot_thermal.py and its temporal-support convention.

Repository organization

src/ and scripts/ preserve the inherited physical implementation and dependencies. V48_LOCAL_PAIR/ contains the verified solver; tools/ provides the supported entry points for this example. V48_PAPER_FINAL/ and V48_UNCERTAINTIES/ retain advanced workflows. examples/case_a is the reference result; docs/ is this site. Legacy scripts remain to preserve imports, but their version numbers do not identify the recommended public entry point.

Validation scope

See VALIDATION_RELEASE.json and AUDIT.md for checks actually performed. The preparation does not rerun the 9024-model search or complete the uncertainty profiles. Additional numerical-resolution tests and broader-object validation remain separate scientific work.
