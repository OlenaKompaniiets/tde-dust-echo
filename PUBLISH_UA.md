# Підготовка публічного репозиторію

1. Розпакуйте архів як окремий проєкт. Не накладайте його на активну папку обчислення похибок.
2. Відкрийте docs/index.html: це готовий сайт документації англійською з 10 сторінками.
3. Перевірте автора/співавторів програмного продукту і оберіть ліцензію. Ми не призначали її без вашого рішення.
4. Завершіть перевірку умов поширення сторонніх таблиць у THIRD_PARTY.md. За потреби замініть їх у публічній версії інструкціями завантаження з перевіркою контрольних сум.
5. Заповніть CITATION.cff.template і перейменуйте на CITATION.cff.
6. Створіть GitHub-репозиторій з узгодженою назвою. Завантажте вміст папки, без results і кешів. Для початкового завантаження всіх файлів зручно використати GitHub Desktop.
7. Settings → Pages → Deploy from a branch → main → /docs → Save.
8. Перевірте сайт за адресою, яку покаже GitHub, і створіть реліз із номером версії. Zenodo/DOI налаштовуються після визначення репозиторію та метаданих.

Підготовка не виконувала публікацію у GitHub. Обчислення похибок і великий грід не перезапускалися. Публічний quick start запускає одну модель Case A.

У пакеті збережено історичні залежності solver: src і scripts. Основний вхід для користувача — tools/run_case_a.py. Універсальний інтерфейс для довільного об'єкта ще не реалізований; конкретні залежності від UGC11487 описані на сторінці Inputs.
